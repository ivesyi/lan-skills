# CRAFT —— 沉淀这行的规矩（单一必读入口）

**每写一张候选卡之前重读一遍，不许凭记忆**——写到第 5 张时，硬门就开始松了。

每条规矩带出处：〔README〕= `knowledge/methodology/README.md`、
〔协议〕= `knowledge/methodology/AGENT-ASSESSMENT-PROTOCOL.md` v1.1
（两者摘录均基于 2026-08-20 仓库版本，**用前回读原文，以仓库当前版本为准**）、
〔Pack 实测〕= 两个方法论 Pack 的字段结构（2026-08-20 于仓库核实）、
〔需求〕= 用户 2026-08-20 口头需求（本手册的设计来源）、
〔实跑〕= 2026-08 诊断报告首次实跑、〔待验〕= 尚无案例，等顾问首跑校准。

---

## §知识库的规矩（本手册跟库的关系）

库里的方法论不是 AI 的常识，是两本书 + 五维框架 + 角色标准，
已由顾问审核后数字化在仓库里。**本手册只往库外产候选，不碰库本身。**

1. **只读不写**。禁改清单见 SKILL.md 边界节。比对现有条目时用当前
   `status` 为 `active` 的那版 pack〔Pack 实测〕；读法优先 `PACK.md`
   （markdown 正文），要核结构化字段再看 `pack.json`。
2. **权威顺序**〔README 原文〕：顾问批准的 Pack 版本 → Pack 中的
   Criterion / Evidence Guidance / Guardrail → 带元数据过滤的本地检索 →
   原书章节或页码核验。**库里没有的东西就是没有依据**——这正是候选
   条目的缺口所在，但缺口不等于可以自己补上去。
3. **转正只能人来做**〔README 原文〕：「Pack 必须人工审核后才能转换为
   机器可加载的 YAML/JSON；任何更新都创建新版本，不覆盖已经被正式判断
   引用的版本。」——为什么这条不能松：库里的旧版本正被已经做出的正式
   判断引用着，覆盖它等于事后改掉别人当初的判断依据。
4. **AI 不能创建准则**〔协议 §7 原文〕：检索「只能定位相关来源、解释
   概念与补充出处；不能创建 Criterion、决定成熟度、覆盖相反证据或直接
   提交正式判断」。所以本手册的产出永远叫「候选」。
5. **谁说了算**〔协议 §1 原文〕：「Agent 负责专业推理和建议；Workbench
   保存事实、版本与状态；顾问负责最终判断。」
6. **非目标里跟沉淀相关的三条**〔README 原文〕：不把任一本书转化为单一
   总分；不用检索相似度代替标准映射（**两条候选长得像不等于是同一条**，
   判重要看它问的问题和适用边界，不是看措辞像不像）；不把成人实践
   方法论用作教师绩效考核。

## §三种卡怎么分

| 这条东西在干什么 | 形态 | 模板 |
|---|---|---|
| 教「怎么判断一件事到位没到位」——是一把尺子，问一个问题 | 候选准则卡 | `templates/criterion-candidate-card.md` |
| 管「判断的时候不许怎么做」——是一条纪律 | 候选护栏卡 | `templates/guardrail-candidate-card.md` |
| 记「这次真发生了什么」——本身不是规律，是以后能拿来参照的一段事 | 案例卡 | `templates/case-card.md` |

**拿不准就先写案例卡**：案例卡门槛最低、最不容易写成废话；等同类案例
攒多了，由顾问决定要不要升成一把尺子〔待验：这条分流规则等顾问首跑确认〕。

## §线索从哪来（Phase 3 采线索）

1. **诊断里反复用到、库里却找不到对应条目的判断依据**——库里没有就是
   没有依据〔README 权威顺序〕，这是最实的缺口。
2. **弃权处**。评不了，常常不是证据不够，而是缺一把尺子——弃权七条里
   就有一条是「缺少明确 StageTarget、Criterion 或角色锚点」〔协议 §5〕。
   〔实跑：首次实跑三处弃权，其中就有缺角色锚点的〕
3. **顾问复盘里的原话**，尤其「下次一定要……」「这种情况就得……」
   ——这类句子往往就是一条护栏的雏形〔需求：复盘是本手册两大输入之一〕。
4. **真实发生、以后能当参照的片段** → 案例卡。库里两个 Pack 的
   `behaviorAnchors` 目前都是空的〔Pack 实测〕——行为锚点正是库里最缺的
   那块，案例卡就是喂它的原料。

线索当场记出处，**记不住出处的直接丢**——事后补出处只会越补越像编的。

## §三道硬门（Phase 4，缺一不收）

1. **写得出适用于 / 不适用于**。理由：库里每条准则都带
   `applicability.appliesTo / doesNotApplyTo`，且 `doesNotApplyTo` 从来
   不是空的（例：某条准则明确写「不适用于：单次课堂评价 / 个人教师绩效
   评定 / 仅凭文本表述判断学校成熟度」）〔Pack 实测〕。写不出边界的条目，
   被用到不适用的场景上就是滥用标准。
2. **写得出反例特征**——「什么情况长得像、其实不是这回事」。理由：库里
   的证据指引是**两组各自可观察**的描述（正面例如「使命被转译为具体的
   学习者理解、能力、态度或长期表现」，反面例如「目标只写活动、口号、
   覆盖率或投入量」），不是一句话取反〔Pack 实测〕。说不出反例的条目
   没有判别力。
3. **写得出案例出处**——见 §溯源。

过不了门的线索，照实退回 `LEADS.md` 并写清卡在第几道门上。
**不许为了凑数把边界含糊写过去**：一条含糊的条目进了库，之后每次误用
都要顾问回头擦屁股，比没有这条更贵。

## §废话卡的样子（一眼假清单，逐条排除）

- 主语是「要 / 应该 / 必须」打头的口号，没有可观察的对象——用户举的
  原型就是「要以学生为中心」式〔需求〕。
- 「适用于」栏写着「所有学校 / 所有场景」，「不适用于」栏写「无」
  ——库里没有任何一条准则是这样的〔Pack 实测〕。
- 正面迹象和反面迹象互为否定（「做到了 X」/「没做到 X」），两边不是
  各自独立可观察的样子〔Pack 实测，见 §三道硬门第 2 条〕。
- 尺子量的是人不是事——读起来像在评某个人称不称职。〔README 非目标：
  不把成人实践方法论用作教师绩效考核〕〔协议 §5：涉及个人绩效的结论
  应弃权〕
- 把「学校」换成「公司」读起来毫无违和，说明它跟这个领域没关系
  〔待验：这条探针等顾问首跑确认好不好使〕。

## §证据基数（每张卡必填）

| 档 | 什么情况 | 措辞纪律 |
|---|---|---|
| **单案假设**（默认档） | 只有这一次活动撑着 | 只能写「在〈这类情形〉观察到一次」。**不许出现「通常 / 一般 / 学校往往」**——一次就是一次 |
| **多案观察（N=〈实数〉）** | 有 N 次不同活动或不同学校撑着 | 每一次的出处都要单独列出来；写成倾向性说法可以，仍标「待更多案例」 |
| **已有条目的补充证据** | 这不是新条目，是给库里某条老准则再加一份证据 | 别当新条目提；卡上写清是给哪条补的 |

**够不够转正的门槛由顾问定，本手册不预设数字**——语料里没有这个数，
编一个不如让顾问首跑时自己定。

## §溯源（三级链，断一级就是现编）

```
候选卡  →  工作文件（事实表第几条 / 主张第几条 / 报告哪一节）  →  原始材料（哪份）
```

- **写卡时必须回工作文件取原文**，不许只凭复盘印象或报告里的概括。
  理由：材料 → 事实 → 报告 → 复盘，每转一手都在压扁信息，末端只剩
  结论、没有细节，拿结论再提炼一次，出来的就是空的。
- **顾问原话逐字引 + 标日期**；记不清逐字的，标「转述（未逐字核）」，
  且转述**不能单独**撑起一张准则卡或护栏卡（可以撑案例卡，注明来源成色）。
- 上游工作文件全程**只读**——它们是这次活动判断的底稿，改了它，之前
  那份诊断的依据就跟着变了。

## §隐私（比诊断报告更严）

诊断报告给顾问看，可以有真名（顾问是授权读者）〔实跑〕。**候选卡不行**
——它是准备入库、以后要跨校复用的东西，一定会脱离这次活动的语境。

- 全部候选卡**一律角色代称**（「某小学中层」「某校校长」），真实校名
  人名一个不留〔需求 + 实跑：曾有虚构人名混进公开配图被抓回〕。
- 候选卡与所有中间产物只落 `.local/` 下的工作区，不入 git。

## §白话（写给顾问看的一切文字）

读者是**不懂技术的教育工作者**——卡片正文和检查点汇报都按这个身份写
〔仓库沟通规范 + 实跑两次现场纠正〕。

- 编号（C-01 / F3 / 准则 ID）只在文件名和索引表里当索引，**不进卡片
  正文的说明句**；
- 不用工程词、不用框架缩写、不用书名里的概念代号——读者没读过那两本书；
- 自测法：把这张卡念给一位没接触过 AI、也没读过那两本书的校长听，
  他能不能不打断地听懂这把尺子在问什么。
