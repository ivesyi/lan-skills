# 方法论沉淀

把一次跑完的活动，变成一批能交给顾问逐条审的**候选**方法论条目。

约定两件事：①下文「用户」指操作本手册的人（顾问本人或项目负责人），
检查点问的就是这个人。②文中所有仓库路径（`knowledge/…`、`.local/…`）
均相对**教育工作台仓库根**，开工前先确认当前目录在仓库根。

## 边界（先说清不管什么）

- **只出候选，不入库**。候选是给顾问审的原料；收 / 改 / 弃由顾问定，
  入库由人工做。理由是库里写死的规矩：Pack 必须人工审核后才能转成
  机器可加载的版本，任何更新都创建新版本、不覆盖已被正式判断引用的
  版本（`knowledge/methodology/README.md` 原文）；判断协议也写死了
  AI **不能创建准则**（`AGENT-ASSESSMENT-PROTOCOL.md` §7）。
- **禁改清单（红线，一个字节都不许动）**：`knowledge/` 下的一切文件——
  两个方法论 Pack 的 `pack.json` 与 `PACK.md`、`README.md`、
  `AGENT-ASSESSMENT-PROTOCOL.md`、`WORKBENCH-METHODOLOGY-CROSSWALK.md`、
  `ontology/` 下所有文件。也**不许在 `knowledge/` 下新建**任何文件或目录。
  这些只读、只引用。本手册唯一允许写入的地方是工作区的 `candidates/`。
- 不做诊断、不写报告、不建工具——沉淀是本手册唯一的活。要出诊断报告
  走 `diagnosis-report`。
- 不评人、不产出任何分数或排名（库的「非目标」第一条：不把任一本书
  转化为单一总分）。

## 输入分诊

| 用户给的东西 | 该做的 |
|---|---|
| 活动工作区路径 + 顾问复盘（文字 / 语音转写 / 飞书链接） | 走完整流程（Phase 1 起） |
| 只有工作区，没有复盘 | 照跑，但线索只来自工作文件；候选卡的「顾问原话」栏写「本轮无复盘」，并在交接说明里标明"未经顾问复盘的候选，可信度更低" |
| 只有一段复盘口述，没有工作文件 | 先反问：这次活动的工作文件在哪。**拿不到工作文件就只能出案例卡**——准则卡和护栏卡的溯源回不到原始材料，等于现编（见 CRAFT §溯源） |
| 什么都没给，只说「沉淀一下」 | 反问四件事：哪次活动、什么时间窗、工作文件在哪、复盘在哪。本手册不替顾问凭空构思方法论 |
| 上一轮候选的修订 / 顾问审完要改 | 定位到该活动的 `candidates/`，在原卡上改，**改动即新版本**（见 Phase 6），不另起炉灶、不悄悄覆盖 |

## 工作区约定

沿用活动本身的工作区（真实材料是他人隐私，`.local/` 不入 git——
开工前确认 `.local/` 在仓库 `.gitignore` 里，不在就先加一行）：

```
.local/<活动简称-时间窗>/       ← 上游产物，全部只读（材料 / 事实表 / 主张 / 报告）
└── candidates/                  ★ 本手册唯一可写的目录
    ├── INDEX.md                 # 候选清单（交顾问逐条审的那张表）
    ├── LEADS.md                 # 未成形线索（没过硬门的，留着不丢）
    ├── C-01-<短名>.md           # 候选准则卡
    ├── G-01-<短名>.md           # 候选护栏卡
    └── E-01-<短名>.md           # 案例卡
```

**上游文件只读**：事实表、主张、报告一个字都不改——它们是这次活动的
判断底稿，改了它，之前那份诊断的依据就跟着变了。

**这棵树里没有 `knowledge/` 是故意的**：知识库在仓库根的另一处，全程
只读、只引用，一个字节都不许动（禁改清单见上文边界节）。本手册全流程
唯一可写的地方就是上面这个 `candidates/`。

`INDEX.md` 骨架（只用这一次，直接照抄）：

```
| 编号 | 形态 | 一句话 | 证据基数 | 与现有库的关系 | 顾问结论 |
|---|---|---|---|---|---|
| C-01 | 准则 | 〔尺子问什么〕 | 单案假设 | 新条目 / 疑似与〔某条〕重复 / 是〔某条〕的补充证据 | 待审 |
```

## 工作流总览

```
Phase 1  定范围（哪次活动 / 时间窗 / 工作文件在哪 / 复盘在哪）
   ▼
Phase 2  对现有库（读一遍现有准则与护栏，列对照——别重复造已有的尺子）
   ▼
Phase 3  采线索（从工作文件 + 复盘里捞，先不写卡）
   ▼
Phase 4  写候选卡（三种形态；过不了三道硬门的当场退回 LEADS.md，不收）
   ▼
Phase 5  自检（字段齐不齐 / 溯源回得去吗 / 有没有碰 knowledge/）
   ▼
[Checkpoint 候选审]  ← 必须停。顾问逐条给：收 / 改 / 弃
   ▼
Phase 6  定稿 + 入库交接说明（怎么人工转正：审后入库、新版本不覆盖）
```

**为什么只停一处**：候选好不好，标准在顾问脑子里，中途问也问不出来；
而一旦顾问逐条审过，剩下的就是誊清。停早了浪费顾问时间，停晚了
（比如已经动手往库里写）就闯红线了。

## 各阶段读文件指南

| 阶段 | 必读（每次都看） | 按需查 |
|---|---|---|
| Phase 2 对现有库 | `references/CRAFT.md` §知识库的规矩 | `knowledge/methodology/*/PACK.md`、`README.md` 原文 |
| Phase 3 采线索 | `references/CRAFT.md` §线索从哪来 | 活动工作区的事实表 / 主张 / 报告 |
| **Phase 4 每写一张卡之前** | **`references/CRAFT.md` 全文** | `templates/` 对应卡片模板 |
| Phase 5 自检 | 本文件 §自检 | —— |

标了"每次都看"的，动手前重读，不许凭记忆——一场长会话写到第 5 张卡时，
硬门就开始松了。

## Phase 1 —— 定范围

四件事，缺一反问：哪次活动（诊断 / 工作坊 / 陪跑节点）、什么时间窗、
工作文件在哪、复盘在哪（谁说的、什么时候说的、是原话还是转述）。

范围锁完，在 `candidates/` 下建 `INDEX.md` 和 `LEADS.md` 两个空壳。

## Phase 2 —— 对现有库

读一遍现有的准则与护栏，列一张对照（**只读，不写**）：

- 两个方法论 Pack 各自管什么、现有准则各问什么问题、现有护栏各禁什么；
- 五维等概念的定义在 `knowledge/ontology/core-v1/` 下。

**读法降级**：优先读同目录的 `PACK.md`（markdown，人能读的版本）；
结构化字段要核时再看 `pack.json`；环境读不了 json 就只用 PACK.md，
并在候选卡的「与现有库的关系」栏写「以 PACK.md 正文比对」。

这一步的目的只有一个：**别重复造已有的尺子**。发现候选跟已有条目撞了，
在卡上标清是「疑似重复」还是「是已有条目的补充证据」——后者根本不该
当新条目提，该提的是给那条老准则补一份证据。

## Phase 3 —— 采线索

从四个地方捞（详见 `references/CRAFT.md` §线索从哪来），先记成一句话
一条，**不急着写卡**：

1. 诊断里反复用到、但库里找不到对应条目的判断依据；
2. **弃权处**——评不了，往往是因为缺一把尺子；
3. 顾问复盘里的原话，尤其"下次一定要……""这种情况就得……"；
4. 真实发生过、以后能拿来当参照的片段（这类走案例卡）。

每条线索当场记下它是从哪儿来的（哪份工作文件的第几条 / 顾问哪句话），
**记不住出处的线索直接丢**——补出处这件事只会越补越像编的。

## Phase 4 —— 写候选卡

按线索的性质选形态（判据见 CRAFT §三种卡怎么分），照 `templates/`
里对应模板写。每张卡写之前**重读一遍 CRAFT.md**。

**三道硬门，缺一不收**（这是本手册最硬的质量闸，理由见 CRAFT §三道硬门）：

1. 写得出**适用于 / 不适用于**——说不清边界的条目，用到不适用的场景上
   就是滥用标准；
2. 写得出**反例特征**——说不出"什么情况长得像但其实不是"，这条就没有
   判别力，是漂亮废话；
3. 写得出**案例出处**——能一路回到工作文件、再回到原始材料。

过不了的，**照实退回 `LEADS.md`**（写清卡在哪道门上），不许为了凑数
把边界含糊写过去。线索不丢，但不进候选清单——顾问的时间只花在成形的
东西上。

写完每张卡，把它登进 `INDEX.md` 一行。

## Phase 5 —— 自检

执行方式按能力降级：能开独立 agent 就让它拿"`candidates/` 路径 + 本节"
逐项核查、汇报 pass/fail + 证据；不能就自己逐项过，**每项写一行结论**，
不许目测放行。**铁律：先修完 fail 项，再汇报。**

- [ ] **红线扫描**：`knowledge/` 下没有任何新增 / 修改 / 删除的文件；
  活动工作区的上游文件（材料 / 事实表 / 主张 / 报告）也未被改动
- [ ] 每张卡五个必填字段齐全：适用于 / 不适用于 / 反例特征 / 证据基数 /
  案例出处——**有一个写着"待补"就是 fail**
- [ ] **溯源抽查**：随机抽 3 张卡，按案例出处回工作文件找原文，找得到吗？
  找不到的卡，删或退回 `LEADS.md`
- [ ] 证据基数默认档正确：只有这一次活动撑着的，一律标「单案假设」，
  且卡里的措辞不是普遍规律的口气（对照 CRAFT §证据基数）
- [ ] 与现有库的关系每张卡都判过（新条目 / 疑似重复 / 是已有条目的补充证据）
- [ ] **隐私扫描**：全部候选卡零真实校名人名，一律角色代称（候选卡是
  准备跨校复用的东西，见 CRAFT §隐私）
- [ ] 对照 CRAFT §废话卡的样子逐条排除
- [ ] `INDEX.md` 与实际卡片一一对得上；模板占位符（〔…〕）清零

## Checkpoint 候选审（**硬节点**）

自检过完必须停，把候选清单交顾问逐条审。汇报模板（全白话）：

```
这次活动能沉淀的东西整理完了，一共 <N> 条候选，都还没进知识库——
按规矩得你先逐条过一遍。

新的尺子（准则）<a> 条：
  C-01 <这把尺子问什么>。适用于 <…>，不适用于 <…>。
       目前只有这一次案例撑着 / 有 <n> 次案例：<各自出处一句>。
       跟现有的关系：<新条目 / 疑似跟某条重复 / 是某条的补充证据>
  ……
判断时的纪律（护栏）<b> 条：
  G-01 <不许怎么做>。这次是在哪儿翻的车：<一句>。
  ……
真实案例 <c> 条：
  E-01 <这是件什么事>。以后能拿来参照 <什么情形>。
  ……
还有 <d> 条没成形的线索（写不出边界或反例，我没收），列在 LEADS.md，
你要是觉得哪条值得，我再回去补。

请逐条给我：收 / 改（改哪儿）/ 弃。审完我誊清，并写一份入库交接说明——
入库这一步按规矩由人来做，我不碰知识库。
```

顾问的结论逐条写进 `INDEX.md` 的「顾问结论」栏；要改的当场改完再复核。
**没审完不许进 Phase 6，任何情况下都不许自己判定"收"。**

**无法与用户交互的环境**（比如被当作一次性任务调用）：不得自行推进，
把候选清单和上面这段汇报写进 `INDEX.md` 顶部，停在此处交人。

## Phase 6 —— 定稿 + 入库交接

1. 按顾问结论誊清：收的留、改的改、弃的移到 `LEADS.md` 末尾（注明
   "顾问弃，理由 <…>"，**不删**——被弃的理由本身是下次的判断依据）。
2. 写一段**入库交接说明**放 `INDEX.md` 顶部，讲清三件事（白话）：
   - 这批候选是从哪次活动、哪些材料里来的；
   - 每条目前有几个案例撑着，够不够转正**由你定**——本手册不预设门槛
     （语料里没有这个数，编一个不如你来定）；
   - 入库怎么走：由人把它转成库里的正式条目；**若是修改已有条目，
     创建新版本、不覆盖已被正式判断引用的那版**（库 README 原文规矩）。
3. 交付：把 `INDEX.md` 和候选卡交给用户（可选：用 lark-cli 建飞书文档；
   建不了就直接交文件路径，由用户自己贴）。交付话术说清：这是候选，
   一条都还没进库。
4. **验收**：问用户——按你的标准，这批候选里有几条是真能用的？
   哪条一看就是废话、哪条边界写歪了？不合格先定位是哪层出的问题
   （线索采得不对 / 硬门放水了 / 只是措辞不对），改最小的那一块，
   不整批重做。

## 出了问题怎么办

用这份手册翻了车（候选全是废话 / 顾问一条都没收 / 溯源对不上 / 差点
碰了知识库），把案例记进 [`FIELD-NOTES.md`](FIELD-NOTES.md)。
翻车不是手册失败，是它变强的原料。
