# 小红书视觉卡片

把一个清晰观点变成可在手机端扫读的封面和轮播卡片。默认使用文字、物件、箭头、便签、对比与轻量结构表达，不生成任何人物、头像、吉祥物或人脸。

需要轮播脚本字段、提示词或视觉验收时，读取 `references/card-guidelines.md`。

## 工作流

### 1. 提炼内容

阅读用户提供的文章、Markdown、链接、截图或草稿。提炼一个核心判断，以及 3–7 个能独立扫读的观点、步骤、坑点、例子或行动建议。

短文通常对应一篇笔记；长文可拆成 2–5 篇系列，但不要为了凑数量稀释内容。

### 2. 先输出内容与脚本

用户只要求转写、方案或脚本时，不生成图片。为每篇笔记输出选题定位、3–5 个标题候选、封面主副标题、正文、5–8 个标签和封面/轮播脚本。

轮播脚本每页写清页面类型、短标题、核心画面锚点、辅助信息、短中文标注及版式层级。默认不需要人物；除非用户提供并授权其自有素材，否则不要在脚本或图中加入人物。

### 3. 设计卡片

每页是一张完整 3:4 竖版白底图像，先确定一个核心画面锚点，例如清单、流程、对比、工具台、检查板、案例现场或结果看板。

围绕锚点安排通常 2–4 组辅助信息。标题和主视觉应最先被看到，随后是关键词、便签、箭头、小卡片、步骤、对比或例子。文字保持短而清楚，保留足够白色呼吸感。

默认规范：

- 白色背景、手绘信息设计、图文并茂但不过满。
- 没有人物、头像、吉祥物、卡通形象或人脸。
- 不设固定配色、模块位置、字号或模板；按文章语义自由组织，但保持清晰阅读顺序。
- 封面必须对应标题承诺，出现具体问题、对象或结果，不能只表达泛泛情绪。

### 4. 生成与编辑

只有用户明确说“生成图片”“做封面”“生成轮播图”“输出 PNG”时，使用内置 `image_gen`。每页单独生成一张完整 3:4 图，不要拼成九宫格，不要请求 API 密钥。

提示词需要明确写出本页标题、核心画面、辅助信息组、短中文标注、白底、手绘信息卡、阅读层级和无人物限制。不要使用 SVG、HTML/CSS、canvas、PIL、脚本或本地代码作为图片替代品。

如需编辑，保持页面标题、核心画面和层级，只改用户指定问题；优先删去冗余文字或装饰，避免把卡片塞满。

### 5. 检查与交付

检查每页是否贴合脚本、手机端可读、主次清楚且有留白。若像单句海报、空白背景上的单个装饰，或像密集工作表，则重新组织信息。

如果在 workspace 中工作，将最终图保存到：

```text
assets/<article-slug>-xhs/cards/
01-cover.png
02-point.png
```

交付时说明页数、每页用途、保存路径，以及哪些页面适合重生成或人工微调。
