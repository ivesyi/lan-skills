# skill-forge

把领域专家的业务经验，锻造成稳定、高效、鲁棒性强的垂类 Agent Skill。

你带着你的业务进来——用你自己的话讲这活儿怎么干、新人会怎么搞砸、
什么样算合格。skill-forge 负责把这些翻译成一个 AI 能稳定执行的 skill，
并且**用你的真实案例跑通一单、你亲自验收合格之后**才算交付。
全程不需要你懂任何 AI 工程。

## 它凭什么做出来的 skill 更稳

多数"skill 生成器"教格式：帮你把想法排版成一份看起来规范的说明书。
skill-forge 的次序反过来——**先挖坑，再造栏杆**：

1. **失败模式驱动**：先访谈出"这活儿容易在哪搞砸、搞砸了返工多贵"，
   每一个流程机制都对着一个真实的坑。没有坑支撑的机制一律不写。
2. **行家的讲究单独萃取**：那些"规矩上没写、老手都懂"的门道会被专门
   挖出来落成原则，且每条都溯源到你的原话或你的材料——AI 不许自己编。
3. **真实案例冷启动验收**：skill 写完后，由一个完全不知道设计过程的
   "陌生 AI"拿你的真实案例跑一单，产出交你按业务标准验收。跑不过就修，
   修完再跑，合格才交付。
4. **越用越强**：交付后翻了车，把案例带回来登记——每个真实的坑都会
   变成 skill 里的防坑条款。

## 怎么用

skill-forge 只要求你的 AI 工具能**读 markdown 文件、写文件**——主流
agent 工具（Claude Code、Cursor 等）都满足。

1. 把 `skill-forge/` 整个文件夹放进你的 AI 工具能读到的位置
   （支持 skill 机制的工具放进其 skills 目录；不支持的，放项目文件夹里
   即可；实在不会放，把 `SKILL.md` 的全文直接发给 AI 也能用）。
2. 开一个新会话，说：

   > 按 skill-forge（〔路径〕/SKILL.md）的流程，帮我把〔你的业务，
   > 比如：我们的合同初审流程〕做成一个 skill。

3. 接下来照着它的节奏走：它会先问你有没有现成材料（手册 / SOP / 好坏
   案例——有就发给它，比访谈快得多），然后用业务问题访谈你，中途会
   停下来跟你确认几次，最后请你提供一单真实的活儿做验收。

## 包内文件

```
skill-forge/
├── SKILL.md                     # 主流程（AI 读的入口，附自身设计图纸）
├── FIELD-NOTES.md               # skill-forge 自己的翻车登记（它也吃自己的药）
├── references/
│   ├── INTERVIEW.md             # 萃取访谈手册（两条路径 + 问题库 + 翻译方法）
│   ├── MECHANISMS.md            # 失败模式 → 机制适应症表（核心资产，19 个机制逐条溯源）
│   ├── PACKAGE-SPEC.md          # 产出 skill 包规格
│   ├── TEST-RUN.md              # 真实案例冷启动试跑协议
│   └── CHECKLISTS.md            # 红线扫描 + 组装完整性清单
└── templates/                   # 骨架模板（产出 skill 三份 + 设计蓝图一份）
```
