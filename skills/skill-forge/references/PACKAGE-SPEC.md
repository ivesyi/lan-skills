# PACKAGE-SPEC —— 产出 skill 包规格

Phase 2.2 按此规格组装。配套模板在 `templates/`（复制后改内容，
模板里的〔指引注释〕全部替换或删除，不许留在成品里）。

## 目录结构

```
<skill-name>/
├── SKILL.md                  # 主流程（骨架件见下节）
├── references/
│   ├── CRAFT.md              # 领域原则 / 品味层（萃取产物；重复环节的单一必读入口）
│   ├── <过程文件规格>.md      # 视需要：中间产物的字段 spec（有唯一真相源时在此钉死）
│   └── CHECKLISTS.md         # 视需要：各产出的自检清单（来自访谈的验收标准）
├── templates/                # 视需要：产出物模板 / 骨架
└── FIELD-NOTES.md            # 翻车登记 + 防坑条款（v1 几乎为空是预期）
```

裁剪原则：目录跟着机制走。没选 M6 就没有 CHECKLISTS.md，没选 M13 就
没有 templates/。**只有 SKILL.md、CRAFT.md、FIELD-NOTES.md 三件必有**
（CRAFT.md 哪怕只有五条原则也单独成文件——它是最常被重读的文件，
不该淹没在流程里）。

## SKILL.md 骨架件（两层，别混）

**第一层：无条件底座件**——与失败模式无关，是可读性 / 可维护性 / 验收
的底座，每个产出 skill 都有：

| # | 底座件 | 说明 |
|---|---|---|
| 1 | frontmatter：name + description | description 写触发场景（用户会怎么说）+ 一句流程概览。这是陌生 agent 决定是否调用本 skill 的唯一依据，按"什么时候用我"来写，不是按"我是什么"来写 |
| 2 | 工作流总览图 | 纯文本流程图；有硬检查点的用 [Checkpoint X] 标出 |
| 3 | 各阶段正文 | 每阶段：进入条件 / 做什么 / 产出物 / 下一步 |
| 4 | 交付 / 验收节（M11，底座件） | 真实产出交用户按业务标准验收 |
| 5 | FIELD-NOTES 指引 | 一句话：出问题登记到 FIELD-NOTES.md，含迭代协议说明 |
| 6 | 附录：机制 ↔ 失败模式映射表 | 设计图纸。迭代改 skill 时照着改，防止后人删了机制不知道它防什么 |

**第二层：机制选型件**——**由 Phase 2.1 的映射表决定，选中对应机制才
写，没选中就没有**。方向是"先论证需要、再写"，不是"先全上、再论证删"
——反过来就是本 skill 批判的货物崇拜次序：

| 选型件 | 前提机制 | 判据一句话 |
|---|---|---|
| 输入分诊表 | M9 | 用户输入形态不唯一才有 |
| 各阶段读文件指南表 | M5 | 有重复环节 / 多 references 才有；单文件短 skill 不需要 |
| 检查点汇报模板 | M2（+M10 底座） | 有用户才能拿的决策才有检查点 |
| 自检协议 | M6 | 有客观可查的清单才有；纯品味领域只留形式完整性检查 |
| 工作区约定 / 目录树 | M16 | 有多个过程产物才有 |
| 其余（锚点 / 真相源 / 契约 / 双源 / 反馈速查…） | M3/M4/M8/M14/M17/M19 | 各按 MECHANISMS.md 适应症 |

## 写作规范

- **语言**：跟随用户的业务语言（中文用户出中文 skill）。语言一致性的
  豁免边界：面向 agent 的执行指令允许必要的英文术语；面向用户的文本
  不允许。
- **黑话边界**（红线 3 的落地）：面向最终用户的文本（检查点模板 / 反问 /
  交付说明）零工程黑话；面向 agent 的执行指令可以用必要的精确术语，
  但优先说人话。对纯小白用户，连 "skill" 一词也算黑话——用户面文本
  改说"操作手册 / 干活方法"这类白话。
- **量化锚**：凡要求 agent 做"合理判断"的地方，尽量给一个从访谈 / 语料
  里来的数值锚（如"每单元 X~Y 为宜"）——没有锚的"合理"每次判的都
  不一样。访谈里挖不出数值就不编（红线 2），留给试跑校准。
- **长度纪律**：SKILL.md 是流程主干，原则细节下沉 references/。判据：
  重复 N 次的环节，其原则必须在单一入口文件里（M5）；只用一次的说明
  直接内联，不另开文件。
- **每条规则给理由**：关键约束旁边用一句话写"为什么"（参照：
  "outline 不写动画的理由：写死动画 = 执行环节退化为翻译机"）。
  陌生 agent 理解了因果才会在边界情况下做对判断；只给禁令，边界情况
  就会瞎猜。
- **能力假设**（红线 4 的落地）：写每一步时自问"只会读 markdown + 写文件
  的 agent 能执行吗？"——不能，就原地写降级路径。
