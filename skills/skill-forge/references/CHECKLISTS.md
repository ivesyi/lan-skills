# CHECKLISTS —— 红线扫描 + 组装完整性清单（Phase 2.3）

执行方式（按能力降级）：①能开独立 agent → 让它拿"skill 包路径 + 本文件"
逐项核查，严格汇报每项 pass/fail + 证据；②不能 → 自己逐项过，**每项写
一行结论**，不允许目测放行。

**铁律：先按 fail 项修完，再进 Phase 3。**

## A. 六条红线扫描

逐条给结论 + 证据（指到具体文件 / 行）：

- [ ] **R1 无主机制**：打开产出 skill 的机制 ↔ 失败模式映射表，SKILL.md
  里出现的每个机制（检查点 / 真相源 / 必读文件 / 自检 / 契约 / 模板…）
  在表里都有对应失败模式行（底座件 M10 / M11 与 PACKAGE-SPEC 第一层
  底座件豁免，记"底座"即可）。反向也查：正文里有没有映射表外的
  "顺手加的"流程装饰。防凑表：抽 2 个机制核对其失败模式行是否真来自
  BLUEPRINT.md，而不是为了过检反向编的。
- [ ] **R2 现编 craft**：CRAFT.md 每条原则都有溯源（用户原话引用 / 语料
  出处 / 用户认可的外部范本 / 试跑案例）。抽查方式：随机挑 3 条，回
  `INTERVIEW-NOTES.md` 或语料里找得到出处吗？找不到的条目 → 删或标记
  "需用户确认"。
- [ ] **R3 工程黑话**：通读所有面向最终用户的文本（检查点汇报模板 / 反问
  话术 / 交付说明），零工程黑话。快速检法：把这些段落单独念一遍，想象
  念给一个完全不懂 AI 工程的业务方听。
- [ ] **R4 能力假设**：逐阶段问"只会读 markdown + 写文件的 agent 能执行
  这步吗？"——依赖高级能力（并行 / 脚本 / 联网 / 特定工具 / 特定文件
  格式的读取 / 与用户中途交互）的每一处，原地有降级路径。易漏的三处
  重点查：外部材料的格式假设、安装落地步骤、检查点处"等用户回复"在
  无交互环境下怎么办。
- [ ] **R5 想象防坑**：FIELD-NOTES.md 里每条防坑条款带案发记录。v1 为空
  或几乎为空 = pass，不是 fail。
- [ ] **R6 未试跑交付**：本清单过完 ≠ 可交付。确认下一步是 Phase 3，
  且交付话术里没有抢跑的"已完成"表述。

## B. 组装完整性清单

- [ ] 目录结构符合 PACKAGE-SPEC.md（三件必有：SKILL.md / CRAFT.md /
  FIELD-NOTES.md；其余目录跟着机制走，没有无机制支撑的空目录）。
- [ ] SKILL.md 骨架件按两层核对（PACKAGE-SPEC.md）：第一层底座件六件
  齐全；第二层选型件每件都有映射表里的机制支撑——出现了没选型依据的
  选型件，按 R1 处理。
- [ ] frontmatter description 按"什么时候用我"写（触发场景 + 用户会怎么
  说），不是自我介绍。
- [ ] 各阶段读文件指南表里的每个文件路径真实存在；references/ 里的每个
  文件都被指南表或正文引用（无孤儿文件）。
- [ ] 重复 N 次的环节有单一入口必读文件，且入口唯一（不需要拼装多个
  文件才能开工）。
- [ ] 模板占位符清零：templates/ 复制来的〔指引注释〕〔占位符〕没有
  残留在成品里。
- [ ] 检查点汇报模板骨架完整：产物清单 / 要对齐的决策 / 等待用户指令的
  明确表述。
- [ ] 关键约束旁有"为什么"：抽 3 条最硬的规则，检查是否给了一句话理由。
- [ ] 语言一致：全包跟随用户业务语言。豁免边界（PACKAGE-SPEC 写作规范）：
  agent 面指令允许必要英文术语；用户面文本不允许，小白画像连 "skill"
  都要换白话。
- [ ] 映射表过 MECHANISMS.md 末节的两条硬规则（底座件豁免；高返工成本
  失败模式无静默漏配）。
