# 单校诊断报告

把一批学校材料变成一份顾问能直接读、能追问到底的诊断报告。
读者是**不懂技术的教育工作者**——报告里的每一句话都要按这个身份写。

约定两件事：①下文「用户」指操作本 skill 的人（顾问本人或项目负责人），
检查点问的就是这个人；报告的读者=顾问。②文中所有仓库路径
（`knowledge/…`、`.local/…`、`packages/…`）均相对**教育工作台仓库根**，
开工前先确认当前目录在仓库根。

## 边界（先说清不管什么）

- 只做**单所学校、一个明确时间窗**的诊断；多校对比、区域生态不在此内。
- 只产出**候选诊断**：AI 负责推理和建议，顾问负责最终判断（评估协议规定的分工）。
- **不打分**：不产出任何数字总分、排名、绩效评级——用户或校方要求打分时，
  说明本方法论明令禁止把标准转化为总分，并提供描述性状态表达作为替代。
- 不建工具、不沉淀新流程——本 skill 的任务只有出报告这一件事。

## 输入分诊

| 用户给的东西 | 该做的 |
|---|---|
| 学校背景 + 材料（飞书链接/文件夹/本地文件） | 走完整流程（Phase 1 起） |
| 只有材料，没说学校/时间窗/要回答什么 | 先反问范围四要素（见 Phase 1），**范围不锁不开工**——缺范围形成的判断是协议明令禁止的 |
| 只说「出个诊断」什么都没给 | 反问：哪所学校、看哪段时间、这次想回答什么问题、材料在哪。本 skill 不替顾问凭空构思诊断对象 |
| 上一轮诊断的追问/修订 | 定位到该校工作区（见下），在原工作文件基础上改，不另起炉灶 |

## 工作区约定

所有真实材料与中间产物落在 `.local/<校名简称-时间窗>/`（`.local/` 已在
.gitignore——**学校数据是他人隐私，一个字节都不许入 git**）：

```
.local/<校名简称-时间窗>/
├── materials/            # lark-cli 拉取的原始材料（只读，不删——判断细节要回这里核）
├── materials-manifest.md # 材料清单：每份材料的类型/内容概述/定位方式/可用性
├── facts.md              # 事实表（编号 F1..Fn）★ 事实编号的唯一真相源
├── evidence-quality.md   # 证据质量结论
├── criteria-mapping.md   # 标准映射（含 Criterion ID 与原书出处）
├── claims.md             # 主张草案（判断+弃权，含正反证据引用）
└── report.md             # 报告成稿
```

**事实编号纪律**：facts.md 是编号唯一出处，下游文件只引用不复制全文；
增删事实后必须顺一遍 criteria-mapping / claims 里的引用（编号漂了，
报告的事实依据就全错位）。

## 工作流总览

```
Phase 1  定范围（学校/时间窗/维度与角色/本次要回答的问题）
   ▼
Phase 2  取材料（lark-cli 拉取 → 材料清单，不可用项如实标注）
   ▼
[Checkpoint 锚定]  ← 必须停。攒批确认：范围四要素 + 人物锚定名单
                     （谁是校长/中层/教师/其他相关方；评谁、不评谁）
   ▼
Phase 3  提事实 + AI 回源自查（不需要用户逐条核对）
Phase 4  查证据质量（汇报即过，用户随时可叫停）
Phase 5  对标准（回 knowledge 库原文，禁止凭记忆）
Phase 6  立主张 + 质证（每条判断带相反证据 + 替代解释）
   ▼
[Checkpoint 主张]  ← 必须停。顾问确认：这些判断对得上现场感觉吗
   ▼
Phase 7  行动与取证计划
Phase 8  成报告（白话）→ 飞书文档交付 →（可选）结构化附录校验
```

为什么只停两处：锚错人是全流程返工最贵的错（事实全挂错人）；主张是顾问
唯一必须亲自把关的东西。事实核对不劳烦顾问——AI 回材料原文逐条自查，
比人工核对更细（顾问确认过这一点）。

## 各阶段读文件指南

| 阶段 | 必读（每次都看） | 按需查 |
|---|---|---|
| Phase 1-2 | 本文件对应节 | `references/CRAFT.md` §资产地图（五维/标准的定义在哪，反问用户前先看） |
| Phase 3 提事实 | `references/CRAFT.md` §事实纪律；**完成后过 `references/CHECKLISTS.md` §A** | `templates/workfiles.md` |
| Phase 5 对标准 | **`references/CRAFT.md` §标准取用协议**（每个维度判断前回读） | knowledge 库 pack 原文（协议要求当场读） |
| Phase 6 立主张 | `references/CRAFT.md` §判断纪律；**完成后过 `references/CHECKLISTS.md` §B** | —— |
| Phase 8 成报告 | **`references/CRAFT.md` §白话规范** + `templates/report-template.md` | —— |
| 交付前 | `references/CHECKLISTS.md` §C | —— |

长会话里原则会淡忘——标了"每次都看"的，动手前重读，不许凭记忆。

## Phase 1 —— 定范围

范围四要素，缺一反问：

1. **学校与阶段**：哪所学校、陪跑到第几学期/哪个阶段、本期目标是什么
2. **时间窗**：诊断锚定哪段时间（一次活动/一个学期/两个节点之间）——
   时间窗决定取哪些材料、能不能谈"变化"（无基线就不许谈跨期变化）
3. **维度与角色**：看全校五维，还是聚焦某些角色（校长/中层/教师/其他）
4. **本次要回答的问题**：这轮诊断为了回答什么（没有具体问题，材料会拉得
   太散，报告会写成泛泛的体检单）

此时只做**初步**锁定——人物锚定要等材料拉完（材料里才看得到有哪些人）。

## Phase 2 —— 取材料

用 lark-cli 逐份拉取：文档 `docs +fetch`、表格 `sheets +cells-get`、
纪要 `minutes +detail`、文件夹先列目录再逐份取。全部落 `materials/`，
生成 `materials-manifest.md`：每份材料一行——类型 / 内容概述 /
定位方式 / **可用性**（表头以 `templates/workfiles.md` 为准）。

- 拉不动的（无权限/空模板/读不了的格式）**如实标"不可用+原因"**，
  绝不假装有数据；材料覆盖不足时宁可缩小结论范围。
- lark-cli 不可用时的降级：请用户把材料导出成文本/截图发过来，或粘贴
  关键内容；来源定位改记"用户提供"。

## Checkpoint 锚定（**硬节点**）

材料拉完后必须停，一次攒批确认（全白话）：

```
材料都拿到了（X 份可用，Y 份不可用：<原因>）。开工前请你锁定几件事：

1. 这次看的是：<学校> · <时间窗> · 要回答「<本次问题>」——对吗？
2. 材料里出现了这些人：<从材料里识别出的人物列表>
   - 校长是：<候选/待确认>
   - 中层是：<候选/待确认>
   - 这些人要不要评：<材料里出现但身份不明的人>
3. 有没有该评但材料里没出现的人？（没材料的只能"不评"，或者你补材料）

已生成：材料包 + 材料清单。锁定后我开始干活，中间不会再逐条来烦你——
细读材料时若冒出新的身份不明人物，我会攒着，到判断确认时一起问。
```

**人物一个都不许猜**：身份不明就列出来问，锚错人=全盘返工。
**无法与用户交互的环境**（如被当作一次性任务调用）：不得自行推进，
把待确认项写入工作文件并停在此处交人。

## Phase 3 —— 提事实 + 回源自查

从材料提取**低推论事实**（只写看得见的言行与记录，评价性语言不混入），
每条带来源定位，编号写入 `facts.md`。纪律见 `references/CRAFT.md` §事实纪律。

**自查代替人工核对**：全部提完后，逐条回材料原文核对——原文找得到吗、
有没有过度推论、主体锚对了吗、定位准吗。核对结果（改了哪几条、删了
哪几条）写在 facts.md 末尾，并过 `references/CHECKLISTS.md` §A。
**不把事实清单抛给用户逐条确认**。

细读中冒出锚定名单之外、身份不明的新人物：事实照提、主体标"待确认"，
**攒批带到 Checkpoint 主张一并问**——这是全流程唯一允许回问身份的口子，
不单独打断用户。

## Phase 4 —— 查证据质量

按六性过一遍：真实性/直接性/多样性/代表性/时效性/可比性，落
`evidence-quality.md`。重点写清：哪些对象证据强（几类来源三角互证）、
哪些薄（单一来源）、哪些**必须在报告里声明的局限**（如自述经 AI 成文、
观察者同时是被评对象、无跨期基线）。向用户一句话汇报结论即过，不等确认。

## Phase 5 —— 对标准

**这一步是书本依据的落点，纪律最严**——完整协议在
`references/CRAFT.md` §标准取用协议，核心三条：

1. 按任务路由选 Pack（学校变革外循环 vs 成人实践内循环），**语义相似
   不能决定标准**；
2. 每个用到的准则，**当场读 pack 原文条目**（含"适用于/不适用于"边界），
   凭记忆概括=违规；
3. 映射结果落 `criteria-mapping.md`，每条带 Criterion ID 与原书出处
   （pack 里有章节页码）——ID 只进工作文件，永不进报告正文。

评不了的板块（无证据/无基线/缺角色锚点）此时就标弃权，不带进主张。

## Phase 6 —— 立主张 + 质证

每条正式判断必须同时具备：可支持也可反驳的表述 / 支持事实 / **相反
证据** / **至少一个替代解释** / 因果检查（机制解释只许说"互相强化"，
不许说"因为 A 所以 B"）。弃权项写明弃权理由和下一步补什么证据。
落 `claims.md`。

## Checkpoint 主张（**硬节点**）

汇报模板（全白话）：

```
判断成形了。过程文件都在工作区（事实表/证据质量/标准映射/主张草案）。

正式判断 <N> 条：
  1. <判断一句话>。凭什么：<一句白话>。反过来看：<相反证据一句>。
  2. ……
不评 <M> 块：<不评什么+为什么评不了>
〔如有〕材料里还冒出几个身份不明的人，顺便帮我认一下：<人物+出处>

这些判断对得上你现场的感觉吗？哪条方向不对、哪条用词不准，直接说。
确认后我成稿。
```

用户修正 → 改 claims.md（连带检查事实引用）→ 重新确认。确认后才写报告。
**无法与用户交互的环境**：同锚定检查点——停在此处交人，不得自行推进。

## Phase 7 —— 行动与取证计划

每条行动给全六件：做什么 / 谁牵头 / 什么时机 / 预期什么变化 / 怎么取证 /
什么情况调整。行动必须能追溯到某条判断，不许提无判断依据的建议。
行动计划不单独立文件，直接成稿于 report.md §8。

## Phase 8 —— 成报告 + 交付

1. 按 `templates/report-template.md` 成稿，**写前重读 CRAFT.md §白话
   规范**——读者是技术小白，编号/缩写/框架名/书名概念全部超纲。
2. 交付前过 `references/CHECKLISTS.md`（黑话扫描/隐私扫描/弃权完整/
   质证完整），逐项写结论，fail 先修再交。
3. 用 lark-cli 创建飞书文档交付（降级：交 report.md 由用户自己贴）。
   交付话术说明：这是候选诊断，哪条要改直接说。
4. **可选增强（二道闸）**：环境有 pnpm 时，可把每条判断转成
   `packages/assessment/src/contracts.ts` 的结构化候选，用
   `validateAssessmentCandidate` + `registryForProfile('active')` 逐份
   校验（跑 `pnpm vitest run packages/assessment/` 里的既有模式），
   机器兜一遍判断结构是否缺件（事实引用/准则引用/置信度/局限）。
   没有该环境直接跳过，报告本体不依赖它。

## 出了问题怎么办

用这个 skill 翻了车（判断离谱/流程卡死/顾问说读不懂），把案例记进
[`FIELD-NOTES.md`](FIELD-NOTES.md)。翻车不是 skill 失败，是它变强的原料。
