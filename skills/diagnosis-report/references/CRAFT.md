对标准前读 §标准取用协议，立主张前读 §判断纪律，写任何给用户看的
文字前读 §白话规范。**每次都重读，不许凭记忆**。

每条规矩带出处：〔协议〕= `knowledge/methodology/AGENT-ASSESSMENT-PROTOCOL.md`
（摘录基于 v1.1，**用前回读原文，以仓库当前版本为准**），〔README〕=

## §标准取用协议（书本依据怎么用）

本项目的判断标准不是 AI 的常识，是两本书 + 五维框架 + 角色标准，
已数字化在仓库 knowledge 库里。**本 skill 不转写任何理论内容，只定
怎么取用**——skill 里出现的一切概括都不是评判依据，pack 原文才是。

1. **权威顺序**〔README 原文〕：顾问批准的 Pack 版本 → Pack 中的
   Criterion / Evidence Guidance / Guardrail → 带元数据过滤的本地检索 →
   原书章节或页码核验。原始 PDF 只用于核验和短摘录。
2. **资产地图**（去哪读）：
   - 学校变革外循环：`knowledge/methodology/schooling-by-design-v1/`
     （pack.json 结构化准则 + PACK.md 原文）
   - 成人实践内循环：`knowledge/methodology/data-wise-v3/` 同上
   - 两套方法与五维/角色标准的分工：
     `knowledge/methodology/WORKBENCH-METHODOLOGY-CROSSWALK.md`
   - 五维等概念定义：`knowledge/ontology/core-v1/*.yaml`
   - 角色标准：仓库根 `references/standards/australian-school-role-professional-standards.xlsx`
     （注意：是**仓库**的 references/，不是本 skill 包的 references/）
     ——**这把尺子目前较粗**（未结构化、无准则 ID、无版本），引用时报告
     里注明"角色对照用的是较粗的尺子"，不假装它和 Pack 同等精细。
     **读不了 xlsx 时**（环境没有表格读取能力）：请用户导出/粘贴相关
     角色的条目文本；拿不到就把角色对照整块弃权——**不得凭常识补
     角色标准的内容**
3. **按任务路由选 Pack**〔协议 step4〕：问"学校整体方向/系统对齐"→ 外循环；
   问"成人日常实践/证据/行动"→ 内循环。**语义相似度不能决定标准**。
4. **当场读原文**〔实跑+用户点名〕：每个用到的准则，打开 pack.json 读该
   条目——`applicability.appliesTo / doesNotApplyTo` 必须核（用在不适用
   的场景=滥用标准）；`sourceLocator` 的章节页码抄进 criteria-mapping.md。
   凭记忆概括准则 = 违规，二手转写丢掉的细节永远回不来。
5. **版本跟仓库走**：用当前 active 版本的 pack——判定方式：pack.json 的
   `status` 字段为 `active`（同 key 多版本并存时用 status=active 的那份；
   拿不准就问用户）。pack 升级不改 skill。引用格式（只进工作文件）：
   `<CriterionID> @ <packId>@<version>（原书：<章节, 页码>）`。

## §五不（书的用法红线）〔README，白话化转述——用前回读原文〕

1. 不把任一本书转化为单一总分；
2. 不用检索相似度代替标准映射；
3. 不把成人实践方法论用作教师绩效考核；
4. 不让外循环方法论取代本项目五维框架；
5. 不保存或展示隐藏思维链——只保存可审核结构（事实/主张/解释/
   置信度/局限/下一步）。

用户或校方要求打分时的回应：说明方法论明令禁止转成总分，提供描述性
状态（如"明显低于阶段目标 / 部分达到 / 基本达到 / 达到且稳定"+ 置信度）
〔四档表述出自 2026-08 实跑中用户批准实施的方案原文〕。

## §事实纪律〔协议 step2/§4〕

- 低推论：只写看得见的言行与记录。「校长说'有意见来找我'」是事实，
  「校长控制欲强」是评价——评价性语言不得混入事实层。
- 每条事实带：来源材料 / 定位 / 主体 / 时间。主体不明的，宁可标
  "主体待确认"也不猜。
- 自查四问（提完逐条过）：原文找得到吗？有没有多推了一步？主体锚对
  了吗？定位准吗？

## §弃权纪律〔协议 §5，摘录基于 v1.1，用前回读原文〕

命中任一条 → 该板块弃权（写"不评+为什么+下一步补什么证据"）或降置信度，
**不得强行定级**：

关键结论只有单一/间接/无法核验来源；样本不能代表所判断的范围或角色群体；
证据与时间窗不一致（含：无跨期基线时不许谈"进步/退步"）；缺阶段目标、
准则或角色锚点；正反证据无法合理解释；分不清事实与评价性语言；涉及个人
绩效、敏感归因或超出顾问授权。

弃权不是失败——「敢说不知道」是这份报告公信力的来源〔实跑：项目经理、
学生成果、顾问自评三处弃权，使用者认可这种"敢说不评"的做法〕。

## §判断纪律〔协议 step5-6〕

- 每条判断可支持也可反驳——写成"谁在什么范围内呈现什么状态"，不写
  放之四海皆准的话。
- **质证义务**：每条判断配相反证据 + 至少一个替代解释。找不到相反证据
  时要写"找过、没找到、这本身是局限"。
- 因果检查：机制解释只许说"这几件事在同一套系统里互相强化"，不许说
  "因为 A 所以 B"〔实跑报告的机制声明就是这么写的〕。
- 判断只到"候选诊断"：接受与否是顾问的事，报告状态栏写明。

## §白话规范（写给用户看的一切文字）〔AGENTS + 实跑两次纠正〕

**语言基准 = 技术小白的教育工作者**。使用者原话：「你一定要考虑使用者的
身份，讲使用者能听懂的语言。」

超纲判定——以下全部不进正文：

- 编号与代号：准则 ID、事实编号、定位符、契约名
- **框架缩写与书名概念**：读者没读过那两本书，书里的模型名、缩写、
  英文名词对他们全是天书——说"这套标准问的是：学校的系统和要干的活
  是不是互相支持"，不说框架代号
- 工程词汇：一切工具名、协议名、文件路径（交付说明里指文件除外）

判断的固定格式〔使用者原话定的〕：**判断（一句白话）→ 判断依据（一句白话
说清用的是哪把尺子、它问什么）→ 事实依据（紧跟判断正下方；可用编号
作索引，但编号只索引不解释）**。

技术细节（事实表/标准映射/结构化附录）只放工作文件，永不进正文。
自测法：把这段念给一位没接触过 AI 和这两本书的校长听，他能不能
不打断地听懂。

## §归档与记忆纪律〔首测用户反馈，FIELD-NOTES #1〕

**知识库归档**（每所学校一个飞书知识库，材料与结论的最终沉淀地）：

- 材料总结**必须带源文引用**：每个要点标注出自哪份原文档 + 原文飞书
  链接，读者顺着引用能回到原文。为什么：总结是二手转写，没有引用链，
  下次没人敢拿它当依据（同一个"回源"思想——本 skill 对方法论 Pack
  怎么讲究，对学校材料就怎么讲究）。
- 总结是归纳不是转抄：明显短于原文，写清"这份材料说明了什么"，
  不搬运原文段落。
- 目录结构首次建库时给用户过目（默认：学校档案/活动材料/诊断报告/
  行动与跟进），归档时放错目录比不放更糟，不确定就问。
- 报告入库用白话版；工作文件（事实表/映射）**不入库**——那是过程
  草稿，进知识库只会淹没真正要看的东西。

**项目记忆（PROFILE.md）**：

- 只记用户**确认过**的事实（人物名单/阶段/知识库地址）+ 客观台账
  （读过什么材料、何时、入库没有）。未经确认的推断不进记忆——
  记忆里混进猜测，下轮会拿猜测当真相。
- 开工先读、收尾必更新；用户新说法与记忆冲突，当场改记忆。
- 记忆是为了**不重复打扰用户、不重复读材料**——不是为了跳过判断：
  历轮的诊断结论只作背景，本轮判断仍从本轮材料出发。

## §隐私纪律〔实跑〕

- 真实材料与全部中间产物只落 `.local/`（gitignored），永不入 git。
- 给顾问的报告可以有真名（顾问是授权读者）；任何**可能外流**的衍生
  产物（公开文章、示例、截图）一律角色代称，交付前扫一遍人名校名。
