# CHECKLISTS —— 自检清单

执行方式：能开独立 agent 就让它拿"工作区路径 + 本文件"逐项核查并汇报
pass/fail + 证据；不能就自己逐项过、**每项写一行结论**，不许目测放行。
铁律：先修完 fail 项，再交付/再推进。

## A. 事实自查（Phase 3 完成时）

- [ ] 每条事实回材料原文找得到（抽不到原文的删或改写）
- [ ] 无评价性语言混入（"强势/优秀/不足"这类词出现在事实层=fail）
- [ ] 每条有主体、来源、定位；主体不明的已标"待确认"，并已列入
  Checkpoint 主张的攒批提问清单（不单独打断用户）
- [ ] 自查改动记录已写在 facts.md 末尾（改了哪几条、为什么）

## B. 映射与主张自查（Phase 6 完成时）

- [ ] 每条判断引用的准则在 pack 里当场读过原文（criteria-mapping.md
  里有该条的原书章节页码为证）
- [ ] 每条准则核过"适用于/不适用于"边界，无用在不适用场景的
- [ ] 每条判断有相反证据 + 至少一个替代解释；没有反证的写了"找过没找到"
- [ ] 机制解释无因果句式（"因为…所以…"出现=fail，改"互相强化"）
- [ ] 弃权七条逐一对照过：该弃权的板块都弃了，弃权理由和补证据方向写了
- [ ] 全文无任何数字总分/绩效评级/排名（描述性状态四档与证据置信度
  不在此列——那是协议允许的表达方式）
- [ ] facts.md 编号与 criteria-mapping / claims 的引用一致（抽 3 条反查）

## C. 交付前扫描（Phase 8 报告成稿后）

- [ ] **黑话扫描**：正文无准则 ID、事实编号、定位符、契约名、框架缩写、
  书名概念、工具名——通读一遍，想象念给没读过那两本书的校长听
- [ ] 判断格式统一：判断 → 判断依据（一句白话）→ 事实依据紧跟其下
- [ ] 报告头声明：候选诊断、时间窗、弃权板块、关键局限
- [ ] 角色标准若用到：已注明"这把尺子较粗"
- [ ] **隐私扫描**：工作区在 `.local/` 且未入 git；若产物会外流，
  人名校名已代称化
- [ ] 行动表每行六件齐全（做什么/谁/时机/预期变化/取证/调整条件），
  且每条行动能指回某条判断
- [ ] 模板占位符清零：report.md 里没有残留的〔…〕/<…> 占位符
